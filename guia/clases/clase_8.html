SQLite y el proyecto final

Aprende a guardar datos en una base de datos real y termina con el proyecto completo del minimarket.

Paso 1 · SQLite: tu primera base de datos

Una base de datos guarda información en tablas, como una hoja de Excel con reglas. SQLite viene incluida en Python (módulo sqlite3) y guarda todo en un solo archivo. Los pasos: conectar (si el archivo no existe, se crea), crear la tabla, insertar, guardar con commit(), consultar y cerrar.

En CREATE TABLE, cada columna tiene un tipo: INTEGER, TEXT. PRIMARY KEY AUTOINCREMENT numera cada fila sola, UNIQUE impide repetidos y NOT NULL impide dejarlo vacío. Los ? reciben los valores por separado, lo que evita la inyección SQL.

"""
PASO 1: Fundamentos de bases de datos con SQLite
--------------------------------------------------
SQLite viene incluido en Python (módulo sqlite3), no requiere instalar
servidor externo.
"""


import sqlite3

# 1. Conectar (si el archivo no existe, se crea)
conexion = sqlite3.connect("clase.db")
cursor = conexion.cursor()

# 2. Crear una tabla
cursor.execute("""
    CREATE TABLE IF NOT EXISTS usuarios (
        id INTEGER PRIMARY KEY AUTOINCREMENT,
        usuario TEXT UNIQUE NOT NULL,
        clave TEXT NOT NULL
    )
""")

# 3. Insertar datos (usar ? evita SQL injection)
cursor.execute(
    "INSERT OR IGNORE INTO usuarios (usuario, clave) VALUES (?, ?)",
    ("admin", "1234")
)
cursor.execute(
    "INSERT OR IGNORE INTO usuarios (usuario, clave) VALUES (?, ?)",
    ("dave", "python123")
)

# 4. Guardar cambios
conexion.commit()

# 5. Consultar datos
cursor.execute("SELECT * FROM usuarios")
filas = cursor.fetchall()
print("Usuarios registrados:")
for fila in filas:
    print(fila)

# 6. Cerrar conexión
conexion.close()

Prueba tú: ejecuta el archivo dos veces: ¿por qué no se duplican los usuarios?

Paso 2 · CRUD: crear, leer, actualizar y borrar

✦

Las cuatro operaciones básicas de toda base de datos, cada una en su función. INSERT crea, SELECT lee, UPDATE modifica y DELETE borra. Siempre con WHERE en las dos últimas: sin él afectarías todas las filas. Fíjate también en el if __name__ == "__main__" final: ese bloque solo corre al ejecutar este archivo directamente. Pruébalo con la tabla de abajo:

"""
PASO 2: CRUD completo
----------------------
Create, Read, Update, Delete.
"""

import sqlite3


def conectar():
    return sqlite3.connect("clase.db")


def crear_usuario(usuario, clave):
    con = conectar()
    cur = con.cursor()
    cur.execute(
        "INSERT INTO usuarios (usuario, clave) VALUES (?, ?)",
        (usuario, clave)
    )
    con.commit()
    con.close()
    print(f"Usuario '{usuario}' creado.")


def leer_usuarios():
    con = conectar()
    cur = con.cursor()
    cur.execute("SELECT * FROM usuarios")
    resultado = cur.fetchall()
    con.close()
    return resultado


def actualizar_clave(usuario, nueva_clave):
    con = conectar()
    cur = con.cursor()
    cur.execute(
        "UPDATE usuarios SET clave = ? WHERE usuario = ?",
        (nueva_clave, usuario)
    )
    con.commit()
    con.close()
    print(f"Clave de '{usuario}' actualizada.")


def borrar_usuario(usuario):
    con = conectar()
    cur = con.cursor()
    cur.execute("DELETE FROM usuarios WHERE usuario = ?", (usuario,))
    con.commit()
    con.close()
    print(f"Usuario '{usuario}' eliminado.")


if __name__ == "__main__":
    
    crear_usuario("prueba", "abcd")
    print(leer_usuarios())
    actualizar_clave("prueba", "nueva123")
    print(leer_usuarios())
    borrar_usuario("prueba")
    print(leer_usuarios())
Prueba tú: inserta «prueba» dos veces, y luego bórrala e insértala de nuevo: mira el número de id.


Paso 3 · Login con ventana y base de datos
Une lo aprendido: la ventana pide usuario y clave, y la base de datos los verifica. fetchone() trae una sola fila, o None si no hay coincidencia, y de ahí sale el True o False. Entry(show="*") oculta la clave al escribir. Fíjate que la clave se guarda tal cual: en un proyecto real se guarda un hash, nunca el texto.
"""
PASO 3: Login con interfaz gráfica (Tkinter) + base de datos (SQLite)
-----------------------------------------------------------------------
Junta todo lo anterior: la interfaz pide usuario/clave, y verificamos
contra la tabla 'usuarios' creada en el paso 1.

"""

import sqlite3
import tkinter as tk
from tkinter import messagebox


def verificar_credenciales(usuario, clave):
    con = sqlite3.connect("clase.db")
    cur = con.cursor()
    cur.execute(
        "SELECT * FROM usuarios WHERE usuario = ? AND clave = ?",
        (usuario, clave)
    )
    resultado = cur.fetchone()
    con.close()
    return resultado is not None


def intentar_login():
    usuario = entrada_usuario.get()
    clave = entrada_clave.get()

    if usuario == "" or clave == "":
        messagebox.showwarning("Campos vacíos", "Completa usuario y clave.")
        return

    if verificar_credenciales(usuario, clave):
        messagebox.showinfo("Bienvenido", f"Login correcto. Hola, {usuario}!")
    else:
        messagebox.showerror("Error", "Usuario o clave incorrectos.")


# ---------- Interfaz gráfica ----------
ventana = tk.Tk()
ventana.title("Login - Clase Python")
ventana.geometry("300x180")
ventana.resizable(False, False)

tk.Label(ventana, text="Usuario:").pack(pady=(20, 0))
entrada_usuario = tk.Entry(ventana)
entrada_usuario.pack()

tk.Label(ventana, text="Clave:").pack(pady=(10, 0))
entrada_clave = tk.Entry(ventana, show="*")
entrada_clave.pack()

boton_login = tk.Button(ventana, text="Ingresar", command=intentar_login)
boton_login.pack(pady=20)

ventana.mainloop()

Resumen
  • sqlite3 guarda tablas en un archivo y no necesita instalar nada.
  • CRUD es INSERT, SELECT, UPDATE y DELETE; los dos últimos llevan WHERE.
  • Los ? pasan los valores por separado y evitan la inyección SQL.
  • El proyecto final reúne ventana, JSON, Excel y gráficos en un dashboard completo.
